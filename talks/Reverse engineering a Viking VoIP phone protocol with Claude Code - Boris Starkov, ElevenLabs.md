## Summary

Boris Starkov, an engineer at ElevenLabs, built a phone-booth demo where picking up a retro red phone connects you to an AI agent voiced by Michael Caine (approved and licensed). The hard part wasn't the voice — it was configuring an old Viking VoIP handset whose setup software only ran on Windows XP, while the ElevenLabs team used Macs. Three senior engineers, working with ChatGPT, had failed to configure it a year earlier.

Starkov used Claude Code as a reverse-engineering partner. It scanned the network to find a usable port, discovered the device spoke in two-letter commands, and brute-forced the command space. Writes appeared to work but vanished on reboot, because they only touched temporary memory. The breakthrough was running the vendor's Windows software in a VM behind a TCP proxy to watch how it actually saved settings — which revealed a binary payload and a one-byte checksum.

He validated the inferred checksum by testing more values rather than trusting a single capture, then packaged the recovered protocol as an open-source Claude Code skill. The final phone routes through Twilio to an ElevenLabs agent. Throughout, Claude directed the investigation while Starkov supplied the hands: rebooting the phone, operating the VM, and counting beeps.

## Key Takeaways

- **The obstacle was a vendor tool, not the voice.** The phone's config software was Windows XP only; the team had Macs.
- **AI as a reverse-engineering partner.** Claude Code explored ports, interpreted error responses, and ran the experiment loop.
- **Undocumented protocol.** No searchable docs existed, so the command structure had to be inferred from device responses.
- **Two-letter commands.** Invalid input returned an "ER" prefix; brute-forcing all two-letter pairs found eight valid commands.
- **Accepted ≠ saved.** Settings applied successfully for the session but disappeared on reboot — persistence was the real goal.
- **Capture beats guessing.** Running the vendor software behind a TCP proxy revealed the save sequence and a binary payload with a one-byte checksum.
- **Verify the inference.** Claude confirmed the checksum by running more values through its proposed calculation.
- **Human in the loop.** Claude orchestrated, but Starkov supplied physical actions the model couldn't take directly.

## Detailed Notes

### Pick up the phone and talk to an agent · 00:15
- On the summit's third floor, an old red telephone connects callers to an ElevenLabs voice agent using Michael Caine's voice.
- The agent walks callers through five questions about British AI history; answer at least one and you can win ElevenLabs swag.
- The booth was built for the summit (introduced with a photo of organizer swyx) — a polished result with a much messier build behind it.

### A Windows XP tool and a Mac-only team · 01:27
- The phone looks retro but has an electronic controller, and its configuration software only ran on Windows XP. The ElevenLabs team all used Macs, and a virtual environment hit driver problems.
- The San Francisco team had bought the phone a year earlier; three senior engineers plus ChatGPT couldn't configure it, so it sat unused.
- After the phone was shipped to London, Starkov tried Claude Code as a reverse-engineering partner.
- The slides themselves were generated by feeding the project conversation to Claude Code as context.

### Find a configuration interface · 03:20
- Target architecture: Viking phone → Twilio → ElevenLabs agent. The phone can only dial a number, so Twilio handles the SIP (call-setup) domain complexity.
- To configure from his Mac, Starkov put a router between laptop and phone, and Claude Code explored the exposed services with Nmap.
- Port 1001 was a false lead — an electronics tunnel. Further probing found a port that actually talked to the phone.
- Sending a probe string got a response, proving a reachable, testable interface. No searchable documentation existed, so the command structure had to be inferred from replies.

### Use error responses to enumerate commands · 05:22
- An invalid string came back prefixed with "ER" plus the string itself — a recognizable rejection response.
- Experiments showed the phone accepted two-letter command codes: some pairs returned the familiar error, others returned something different.
- Once the command width was known, guessing became enumeration — Claude Code tried every two-letter combination and sorted errors from interesting replies.
- Eight two-letter combinations returned non-error responses and were treated as valid commands. Names were hints, not full meanings (he tentatively associates "SA" with status).
- With responsive commands in hand, the next step was writing the credentials the phone needed to place a call.

### Accepted settings aren't saved settings · 07:15
- The configuration commands appeared to work, and the phone accepted the settings for connecting to the Twilio SIP trunk.
- Then a reboot erased everything: the writes had changed temporary memory without persisting. A successful write response wasn't the real success condition — surviving a reboot was.
- They spent hours hunting for persistence, expanding to three-letter codes and plausible words, and found nothing.
- Starkov says this was roughly where the earlier San Francisco effort had stopped.

### Capture how the vendor software does it · 08:54
- Claude proposed running the vendor's Windows configuration software in a VM; Starkov hit a Wi-Fi bridging and connectivity issue on his macOS setup.
- Claude's fix was a TCP proxy on the Mac — both a connectivity workaround and an observation point.
- The method was a man-in-the-middle setup: run the vendor software in the Windows VM, point it at the Mac proxy, relay traffic to the phone, and log bytes in both directions.
- The vendor app already knew how to configure the device, so instead of guessing more commands they watched the working operation happen.

### Infer the checksum, then test the inference · 10:33
- The capture revealed a "TS" command with a binary payload; most parameters made sense except a one-byte checksum.
- One byte makes brute force practical, and the captured traffic supplied both the transmitted data and the observed result, constraining the calculation.
- He describes the arithmetic as a simple addition or subtraction involving a one-byte value. He also calls it encryption, but the described mechanism is a checksum.
- Crucially, Claude didn't just fit one capture: it ran additional values through the inferred calculation to confirm the behavior — closed-loop checking rather than wishful fitting.
- At that point Starkov considered the protocol substantially understood.

### From a cracked protocol to a reusable skill · 12:17
- Understanding the vendor traffic revealed the sequence needed to make settings persistent — the missing piece.
- They also decoded a 256-byte memory area in the phone, giving enough to program the device directly.
- With the protocol known, Starkov could factory-reset the phone and configure it without launching Windows. He packaged the knowledge as an open-source Claude Code skill.
- The recovered protocol had two layers: text commands (found by probing) and binary behavior (found by capture). He credits the lucky one-byte checksum — a harder scheme would have been much harder to break.
- The final Twilio-to-ElevenLabs integration was easy, and reverse engineering took about a couple of days. He frames AI as making the demo possible, not merely faster.

### The human supplied the hands — and the connection · 16:57
- On cost: he gives a spend estimate of $10–$100 on the corporate account, not a token count.
- Claude did not control the Windows VM; Starkov operated it manually by following Claude's instructions.
- The same division applied physically: Claude asked him to lift the handset and count beeps; he first said three, then corrected to two when Claude said the expected options were two or four.
- He describes himself as Claude's "hands" — he could reboot the phone and control the VM, but couldn't independently solve the algorithmic reverse-engineering.
- Physical setup: the phone's black cable used Power over Ethernet (PoE — Ethernet data and power combined through an adapter) to a router; his laptop joined the same router over Wi-Fi, and Claude found the phone by listing connected devices.
